## 3. Assumptions and Design Decisions

- **Naming:** tables are named `bz_<tablename>` (lowercase) in `workspace.bronze`. Source column names are kept as in the source (uppercase). Databricks resolves column names case-insensitively.
- **Only one source entity:** the source model has one table, SHIPMENT, so there is one business Bronze table, `bz_shipment`.
- **Excluded columns:** SHIPMENT_ID (the source primary key) is excluded, as in the logical model. The source declares no foreign keys, so all other `*_ID` / `*_CODE` columns are kept as ordinary columns. This is an inference.
- **Source columns only:** columns flagged "(not used)" or "(removed from reporting)" in the source are kept, because Bronze is raw ingestion.
- **No constraints:** there are no PRIMARY KEY, FOREIGN KEY, NOT NULL or CHECK constraints. Bronze is a raw landing zone, so all columns are nullable. The NOT NULL flags in the source (CREATED_DTTM, CREATED_SOURCE, SHIPMENT_STATUS, SHIPMENT_TYPE, TC_COMPANY_ID, TC_SHIPMENT_ID) are not enforced.
- **Data types:** VARCHAR → STRING, DATETIME → TIMESTAMP, DECIMAL(p,s) → DECIMAL(p,s), INT → INT. Y/N flags stay STRING, as in the source.
- **Metadata columns:** load_timestamp, update_timestamp (TIMESTAMP) and source_system (STRING) are added to bz_shipment. update_timestamp is separate from the source column LAST_UPDATED_DTTM.
- **Audit table:** `bz_audit_log` has record_id, source_table, load_timestamp, processed_by, processing_time, status and row_count. processing_time is DOUBLE (seconds, inferred) and row_count is BIGINT. This follows the Bronze physical standard. The logical model listed processing_time as DECIMAL(10,2) and had no row_count, so this is a deliberate change.
- **Storage:** Delta format (`USING DELTA`). No partitioning or clustering is defined, because the source gives no volume or access-pattern information.
- **PII:** the PII classification in the logical model applies unchanged. No masking is applied at Bronze. This is left to governance.
- **Landing schema / seeding:** the source landing schema `tms_landing` was not used. The DDL contains no data loading, so no seeding was done.
